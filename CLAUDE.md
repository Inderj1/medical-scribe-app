## Project Overview

This is an AI-powered medical scribe application that provides medical documentation through batch audio processing. It accepts audio file uploads, transcribes them using OpenAI's Whisper API, and generates structured clinical notes.

## Essential Commands

### Running the Application
```bash
# Full setup and run (installs dependencies, runs migrations, starts both services)
./run.sh

# Quick start (skips dependency updates)
./run.sh --quick

# Backend only
./run.sh --backend-only

# Frontend only  
./run.sh --frontend-only

# Stop all services
./stop.sh
```

### Development Commands

## High-Level Architecture

### Agent-Based System
The application uses OpenAI's Agents SDK with specialized agents:
- **TranscriptionAgent** (`backend/app/agents/transcription_agent.py`): Handles audio file processing via Whisper API
- **ClinicalContextAgent** (`backend/app/agents/clinical_context_agent.py`): Extracts medical entities
- **NoteStructuringAgent** (`backend/app/agents/note_structuring_agent.py`): Formats clinical sections
- **MedicalScribeSupervisor** (`backend/app/agents/medical_scribe_supervisor.py`): Orchestrates agents

### API-Based Processing Flow
1. Client uploads audio file to `/api/v1/transcription/upload`
2. Audio processed via OpenAI Whisper API
3. Agents analyze transcription and structure content
4. Frontend polls for updates and receives progressive section completion

### Database Schema
- **Users**: Authentication and profile data
- **Encounters**: Recording sessions with patients
- **Transcriptions**: Raw transcription data
- **ClinicalNotes**: Structured medical documentation
- **Patients**: Patient demographics and history

### Frontend Architecture
- React Context for global state (`AuthContext`, `WebSocketContext`)
- Material-UI components with custom theming
- Service layer pattern for API/WebSocket communication
- Real-time updates via WebSocket event handlers

## Key Implementation Details

### API Endpoints
- `POST /api/v1/transcription/upload`: Upload audio file
- `GET /api/v1/transcription/{id}/status`: Poll for transcription status
- `GET /api/v1/transcription/{id}`: Get complete transcription
- `GET /api/v1/transcription/{id}/qa`: Get quality assurance results
- `POST /api/v1/encounters`: Create new encounter

### Authentication Flow
1. Clerk handles user authentication
2. JWT tokens passed in API headers
3. Backend validates via middleware
4. Session managed in Redis

### EHR Integration
- FHIR-based integration for Epic/Cerner
- Patient data sync via `/api/v1/ehr/sync-patient`
- Vitals import from connected systems
- Export to HL7/FHIR formats

## Critical Patterns

### Performance Optimization
- Efficient audio file processing

```
REDIS_URL=redis://localhost:6379

```
