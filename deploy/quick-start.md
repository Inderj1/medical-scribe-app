# 🚀 Quick Start: Deploy Medical Scribe on AWS with Terraform

## Prerequisites Checklist

- [ ] AWS Account with billing enabled
- [ ] AWS CLI installed and configured (`aws configure`)
- [ ] Terraform installed (v1.0+)
- [ ] SSH key pair (`~/.ssh/id_rsa.pub`)
- [ ] API Keys ready:
  - [ ] Clerk Secret Key
  - [ ] OpenAI API Key
  - [ ] GitHub repository URL

## 1️⃣ First Time Setup (5 minutes)

```bash
# Clone the repository
git clone <your-repo-url> medical-scribe-app
cd medical-scribe-app

# Install Terraform (if needed)
# macOS
brew install terraform

# Linux/WSL
wget -O- https://apt.releases.hashicorp.com/gpg | gpg --dearmor | sudo tee /usr/share/keyrings/hashicorp-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] https://apt.releases.hashicorp.com $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/hashicorp.list
sudo apt update && sudo apt install terraform

# Configure AWS
aws configure
# Enter your AWS Access Key ID
# Enter your AWS Secret Access Key
# Default region: us-east-1
# Default output format: json
```

## 2️⃣ Deploy Infrastructure (10 minutes)

```bash
# Navigate to deploy directory
cd deploy

# Run the deployment script
./terraform-deploy.sh
```

The script will:
1. ✅ Check prerequisites
2. 📋 Create infrastructure plan
3. 💰 Show cost estimate (~$78/month)
4. 🚀 Deploy after confirmation

## 3️⃣ What Gets Created

| Resource | Type | Cost |
|----------|------|------|
| EC2 Instance | t3.large (8GB RAM) | ~$60/month |
| RDS PostgreSQL | db.t3.micro | ~$15/month |
| VPC + Subnets | Networking | Free |
| Security Groups | Firewall rules | Free |
| Elastic IP | Static IP | Free |
| EBS Storage | 30GB SSD | ~$3/month |

## 4️⃣ Post-Deployment Setup (5 minutes)

After Terraform completes, you'll get:
- 🌐 **Server IP**: `XX.XX.XX.XX`
- 🗄️ **Database**: RDS endpoint
- 🔐 **Credentials**: Saved securely

### Connect to your server:
```bash
# SSH into the EC2 instance
ssh -i ~/.ssh/id_rsa ubuntu@<YOUR_SERVER_IP>

# The server is pre-configured with:
# ✅ Docker & Docker Compose
# ✅ Nginx reverse proxy
# ✅ PostgreSQL client
# ✅ Automated backups
# ✅ SSL ready (Certbot)
```

### Deploy the application:
```bash
# On the server, clone your code
cd /opt/medical-scribe
sudo docker-compose up -d

# Check status
sudo docker-compose ps
```

## 5️⃣ Access Your Application

1. **Direct IP Access**:
   ```
   http://<YOUR_SERVER_IP>
   ```

2. **Domain Setup** (Recommended):
   - Point your domain to the Elastic IP
   - Run: `sudo certbot --nginx -d yourdomain.com`

## 6️⃣ Environment Variables

The deployment creates `/opt/medical-scribe/.env` with:
```env
DATABASE_URL=postgresql://medscribe:password@rds-endpoint:5432/medical_scribe
REDIS_URL=redis://localhost:6379
SECRET_KEY=<auto-generated>
CLERK_SECRET_KEY=<your-key>
OPENAI_API_KEY=<your-key>
```

## 💡 Cost Optimization Tips

1. **Stop during development**: 
   ```bash
   aws ec2 stop-instances --instance-ids <instance-id>
   ```

2. **Use Reserved Instances**: Save 40-60% for 1-year commitment

3. **Enable auto-stop**: Use AWS Lambda to stop at night

## 🚨 Troubleshooting

**Can't connect to server?**
- Check security group allows your IP for SSH
- Verify instance is running: `aws ec2 describe-instances`

**Application not loading?**
- Check Docker: `sudo docker-compose ps`
- View logs: `sudo docker-compose logs app`
- Verify Nginx: `sudo systemctl status nginx`

**Database issues?**
- Test connection: `pg_isready -h <rds-endpoint>`
- Check security group allows EC2 to RDS
